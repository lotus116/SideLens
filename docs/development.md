# 验证与迭代记录

## 验证与迭代

比较同一份材料下的主线复盘、普通独立第二意见、SideLens 独立审视。首轮合成案例检查：能否发现影响决定的问题、正常探索时是否克制、是否尊重目标变更，以及建议是否有可执行的验证。合成案例是冒烟检查，不能证明减少真实返工。

真实试用每次只需记录：提醒是否成立；是否改变下一步；验证后发生了什么；有没有无谓打断。根据观察到的失败修订，避免不断累积规则。

只有发现 Skill 在触发、上下文获取或结果交接上有反复出现且无法合理解决的缺陷，才考虑升级形态。独立意见本身无增益时，先改审视方法，不急着开发更大的产品。

## 首轮试跑（2026-11-04）

本地输出保存在 `sidelens-workspace/`，不作为技能发布内容提交。两名新上下文审视者分别使用 SideLens 和普通第二意见方式，每名处理四个合成案例。普通第二意见也发现了主要问题；本轮尚未证明 Skill 有额外收益。

这轮只覆盖审视者的回答，不覆盖主线真实复盘、自动触发、完整交接流程或真实返工。每种方式只有一次采样，同组四题共用一个上下文，也不是盲评。未取得可靠的耗时和 token 用量，不报告成本比较。

案例1包含“最多再做两项诊断”与已完成三轮的时间顺序歧义。双方都注意到额度问题；保留原题和原始输出，不把合理的约束核对误算成无谓打断。下一轮应拆分成额度明确充足和额度已耗尽两个版本。

当前最值得做的下一步：在真实任务中手动试用，记录一次提醒前的待决事项，以及提醒后实际作了什么；随后再验证主动调用时机。若普通第二意见持续同样有效，应进一步缩短 Skill，而不是为了证明产品必要而增加流程。
